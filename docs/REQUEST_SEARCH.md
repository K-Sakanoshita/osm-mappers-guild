# 依頼検索とページ送り

`GET /requests` は `status`、`category`、`owner=me`、`participating=me` を組み合わせられます。地域の依頼には `area=located&bbox=西端,南端,東端,北端` を指定します。依頼の矩形が範囲に重なる場合は境界上も含めて取得します。

- 経度は −180〜180、緯度は −90〜90 の有限数値を指定します。南端は北端より小さい値にします。
- 西端が東端より大きい指定は日付変更線をまたぎます。全世界は `-180,-90,180,90` で指定できます。
- `area=worldwide` で場所指定なしの依頼を取得します。無効な bbox や `area=worldwide` と bbox の併用には HTTP 400 を返します。
- `limit` は 1〜100 です。返却された `next_cursor` を同じ検索条件で次の `cursor` に指定します。最終ページの `next_cursor` は `null` です。無効な `limit` や `cursor` には HTTP 400 を返します。
- 更新日時と ID の降順で取得します。`limit` と `cursor` を省略した従来のリクエストは最大100件の `{requests}` を返します。`cursor` のみを指定した場合は最大30件です。

地図とサイドバーには同じ検索結果を30件ずつ追加します。マイページの依頼一覧も30件ずつ取得でき、地図の表示範囲とは独立しています。1レスポンスは最大100件です。各依頼には詳細ページと同じ説明文（最大5,000文字）が含まれます。

## 負荷計測

ローカルの MySQL 8.4 と PHP 8.5 で、同じ更新日時を持つテスト依頼を投入して先頭30件を取得しました。初回を除いた各条件15回の HTTP 応答時間の中央値です。地域検索には100件のデータでは約半分、1,000件以上では約2割が該当します。全世界の範囲には場所指定なしの1件を除く全件が該当します。1件あたりの説明文は180文字です。

| DBの依頼数 | 地域検索 | 全世界の範囲 | 該当なし |
| ---: | ---: | ---: | ---: |
| 100 | 5.0 ms | 2.4 ms | 2.1 ms |
| 1,000 | 15.5 ms | 3.0 ms | 9.9 ms |
| 10,000 | 126.4 ms | 13.4 ms | 81.6 ms |

30件のレスポンスは約28.6 KBでした。bbox 検索では候補行の GeoJSON から矩形の端を計算します。狭い範囲でも候補行を走査するため、依頼数とともに応答時間が伸びます。全世界の範囲では座標計算を省略し、参加者といいねの集計は選択したページに限ります。

Chrome のヘッドレスモードで、近接した点を MapLibre の GeoJSON ソースに一度に設定した場合も計測しました。同じ地図で計5回の中央値です。

| GeoJSONの点数 | ソース更新イベントまで | 描画が静止するまで（`idle`） |
| ---: | ---: | ---: |
| 100 | 40 ms | 312 ms |
| 1,000 | 43 ms | 320 ms |
| 10,000 | 49 ms | 335 ms |

既存の GeoJSON を MySQL と SQLite で直接検索するため、この変更に DB マイグレーションは不要です。公開時は対応する API を先に配置し、その後にフロントエンドを公開します。
